AuraUI 2 Documentation

The secure, high-performance C++20 desktop framework powered by in-process native webviews, zero-trust capabilities, and compact single-binary executables.

AuraUI 2.0 Pure C++20 Zero Exposed Ports ~750 KB Standalone Binary Zero-Trust Sandbox

⚡ Introduction

AuraUI 2 bridges high-performance C++20 backend logic with modern HTML5, CSS3, and JavaScript frontends. Unlike Electron which bundles a ~150 MB Chromium runtime and Node.js environment, AuraUI uses the host operating system's native in-process webview:

  • Windows 10 / 11: Microsoft Edge WebView2 (in-process native control).
  • macOS 12+: WKWebView via Cocoa / AppKit.
  • Linux: WebKitGTK (libwebkit2gtk-4.1).

AuraUI 2 eliminates open HTTP/WebSocket servers entirely. All communication between the frontend and C++ engine passes through an audited, in-process IPC bridge (window.__aura_ipc) governed by a deny-by-default capability manifest (aura.config.json).

🏗️ Architecture Overview

Communication between frontend webviews and the C++ engine passes through an audited in-process choke point with rate limiting and strict payload caps:

AURAUI 2 IN-PROCESS IPC ARCHITECTURE 
+-------------------------------------------------------------+
|             Frontend (HTML5, Modern CSS, ES6 JS)            |
|       aura.call("cmd", data)  <-->  aura.on("event", fn)    |
+-------------------------------------------------------------+
                               ↕ [window.__aura_ipc(envelope)]
+-------------------------------------------------------------+
|    Zero-Trust Security Gateway (aura.config.json & Limits)   |
|   * Rate Limiter (100 req/s)   * Max 1 MiB Payload Cap      |
|   * Capability Whitelist Guard * Dispatcher Choke Point     |
+-------------------------------------------------------------+
                               ↕ [Type-Safe auraui::Context]
+-------------------------------------------------------------+
|             Backend: Pure C++20 Engine (auraui.hpp)         |
|   app.bind()  |  app.route()  |  app.emit()  |  Middleware  |
|   Native OS Modules: Dialogs, Clipboard, Shell, System      |
+-------------------------------------------------------------+

⚡ Quick Start

AuraUI 2 projects use CMake 3.24+ with presets for consistent cross-platform compilation:

BASH / POWERSHELL 
# 1. Clone repository
git clone https://github.com/Byukusenge-Andrew/auraui.git
cd auraui

# 2. Configure build with CMake Preset
cmake --preset win-msvc-release

# 3. Compile standalone release executable
cmake --build --preset win-msvc-release

# 4. Run tests
ctest --preset unit-tests

🔒 Project Manifest & Capabilities (aura.config.json)

AuraUI 2 implements a Deny-by-Default Zero-Trust Capability Model (ADR-003). Native system capabilities must be explicitly declared in aura.config.json:

JSON (aura.config.json) 
{
  "app": {
    "name": "kredita-desktop",
    "version": "2.0.0",
    "title": "Kredita — Retail Ledger"
  },
  "window": {
    "width": 1180,
    "height": 780,
    "min_width": 900,
    "min_height": 600,
    "frameless": true
  },
  "security": {
    "capabilities": [
      "window.minimize",
      "window.maximize",
      "window.close",
      "dialog.open",
      "dialog.save",
      "clipboard.read",
      "clipboard.write",
      "shell.open",
      "system.info"
    ],
    "rate_limit_per_sec": 100,
    "max_payload_bytes": 1048576
  }
}

Declared Capability Matrix

Capability Token Permitted Operations Default Status
window.* Minimize, maximize, restore, close, and set titlebar text. Denied
dialog.open / dialog.save Native OS file picker dialogs with Powerbox grant isolation. Denied
clipboard.read / clipboard.write Operating system clipboard inspection and write operations. Denied
shell.open Launch default browser for whitelisted protocols (https, http). Denied
system.info Query system telemetry (RAM usage, CPU, platform version). Denied

⚙️ C++ Backend Guide (auraui.hpp)

All types and framework classes reside under the auraui namespace.

Application Options & Lifecycle

C++ 
#include "auraui.hpp"

int main() {
    auraui::AppOptions opts;
    opts.title = "AuraUI 2 Application";
    opts.width = 1180;
    opts.height = 780;
    opts.asset_path = "ui";            // Auto-detects "ui" or "dist"
    opts.manifest_path = "aura.config.json";

    auraui::App app(opts);

    // Register audit logger middleware
    app.use(auraui::middleware::logger());

    // Run event loop
    return app.run("index.html");
}

Route & Command Handlers

C++ 
// 1. Direct function binding
app.bind("math.add", [](const auraui::Context& ctx) {
    int a = ctx.get<int>("a", 0);
    int b = ctx.get<int>("b", 0);
    return auraui::json{{"result", a + b}};
});

// 2. Express-style REST route
app.route("api/user", [](const auraui::Context& ctx) {
    std::string id = ctx.get<std::string>("id", "");
    return auraui::json{{"id", id}, {"role", "admin"}};
});

Context Object (auraui::Context)

The context exposes the request command name, ID, arguments, and type-safe extractors:

C++ 
app.bind("orders.submit", [](const auraui::Context& ctx) {
    std::string customer = ctx.get<std::string>("customer", "Guest");
    double total = ctx.get<double>("total", 0.0);

    if (ctx.has("items")) {
        const auto& items = ctx["items"];
        // Process items...
    }
    return auraui::json{{"status", "created"}};
});

Middleware & Error Handling

C++ 
// Middleware chain with early abort
app.use([](auraui::Context& ctx, auraui::Next next) {
    if (ctx.cmd().starts_with("secure.") && !ctx.has("token")) {
        return auraui::make_error(auraui::ErrorCode::permission_denied, "Token required");
    }
    return next(ctx);
});

In-Process Native IPC (aura.call)

    }
}

📐 Architecture Decision Records (ADRs)

AuraUI 2 architecture is governed by formal decision records:

ADR Title Status Core Decision
ADR-001 Window Backend Architecture Accepted In-process native webview controls (WebView2, WKWebView, WebKitGTK) replacing external browser processes and local HTTP servers.
ADR-002 Unified IPC Envelope & Dispatcher Accepted Single in-process bridge window.__aura_ipc with strict JSON envelope, 1 MiB payload cap, and central dispatcher.
ADR-003 Zero-Trust Capabilities System Accepted Deny-by-default permission model in aura.config.json with Powerbox opaque grant tokens for file access.
ADR-004 Asset Serving & Origin Isolation Accepted Embedded asset serving via in-memory loopback transitioning to native custom scheme aura://app with strict CSP.
ADR-005 Error Handling Across Boundaries Accepted tl::expected<T, Error> across all internal boundaries returning stable JSON error codes.
ADR-006 Build System and Presets Accepted CMake 3.24+ with CMakePresets.json as the single source of truth across all platforms and CI pipelines.
ADR-007 Universal UTF-8 Internal Encoding Accepted UTF-8 everywhere internally, with platform adapters handling UTF-16 wide string conversions on Windows.

❓ Troubleshooting & FAQ

Q: How do I compile and distribute a standalone release?

Run cmake --preset win-msvc-release and cmake --build --preset win-msvc-release. The resulting binary in build/Release runs standalone on Windows 10/11 with zero installers.

Q: Can I use modern web frameworks like React, Vue, or Svelte?

Yes. Set your bundler (Vite, Webpack, etc.) to emit into the ui/ directory. AuraUI will automatically detect and serve your frontend assets.
